# Pilot training contract

The run saves an immutable, versioned `training-config.txt` with SHA-256 identity beside each checkpoint. It binds the exact 50,483,200-parameter model, tokenizer/dataset digests, context 32, stride 32, batch 2, AdamW semantics, β₁=.9, β₂=.999, ε=1e-8, decoupled decay=.01, global gradient clip=1, initialization seed 26167, shuffle seed 42, total one-pass step target, validation/probe/checkpoint cadence and 600-second wall ceiling. Resume compares the complete canonical configuration. The core FP32 checkpoint retains its CRC-protected model/optimizer state and atomic save. A separately atomic `.meta` sidecar binds model architecture, config/dataset/tokenizer identities, checkpoint SHA-256, step/positions and last LR. Both files must verify before resume.

Pilot peak LR is **1e-4**, minimum **1e-5**, with a 100-step linear warmup and cosine decay through the one-pass step count. This is one tenth of the 0.001 smoke LR because the corpus is tiny and this loop tests stable training, not fast memorization. No hyperparameter sweep is performed. `LearningRateSchedule::at(step)` is deterministic: first optimizer step uses peak/warmup, warmup's last step uses peak, total's last step uses minimum. AdamW receives the scheduled FP32 LR; all other optimizer mathematics stay unchanged.

Validation runs before optimization, then on a canonical first-128-window sample every 200 steps and on all validation windows at the end. It uses `forward_loss` only. The test partition remains sealed. A fixed ten-prompt probe suite runs at step 0, every 400 steps and after training, recording greedy and fixed-seed temperature .8/top-40 outputs without filtering. Telemetry is flushed every 50 steps and includes loss, perplexity, LR, gradient norm/clip, positions, rate, elapsed time and RSS. Periodic checkpoints are saved every 400 steps; only the two newest checkpoints **from this run** are retained, plus the final checkpoint. An error preserves the latest valid checkpoint and telemetry; no hyperparameter is changed automatically. The pilot never initializes from the Loop 6D four-step smoke checkpoint.

Future runs can set reporting-only thresholds `JADE_WARN_LOSS_FACTOR`, `JADE_WARN_GRADIENT_NORM` and `JADE_WARN_THROUGHPUT_FRACTION`; defaults are 5, 100 and 0.25. The policy is written to `warning-policy.txt` and does not alter the optimizer. This warning-policy option was added after the recorded pilot; the pilot used the same default loss/norm checks, while interval throughput is preserved in its telemetry for inspection.
