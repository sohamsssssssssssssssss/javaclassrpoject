# JADE BPE artifact v1

`data/tokenizer/jade-bpe-1024.v1` is the saved artifact for the existing train-fitted 1024-token byte BPE used by the chat baseline. It was migrated from the existing 768-rule `jade-engine/data/merges-1024.txt`; Java rebuilds all 256 base byte tokens and merged token byte strings, validates uniqueness and merge dependencies, then writes the artifact. Its recorded source-corpus manifest digest is Loop 5D's `1ee4db08e1af1b8f7540021801cc4c4774142bad20c67a76977d57174a41d6ba`; the original BPE fit used a bounded **train-only** sample of that corpus. The digest names the overall source manifest, not the exact fit-sample bytes. This artifact is frozen for the pilot; the new pilot dataset does not refit BPE.

The ASCII format begins `JADE-BPE-1`, followed by `vocab=1024`, `corpus=<SHA-256>`, `merges=768`, 768 ordered `left right result` rules, and a final `sha256=<SHA-256>` of every prior byte. Base IDs 0–255 equal byte values. Each result ID is sequential, starting at 256; token bytes are the concatenation of the two inputs. The merge order is the BPE rank. Both Java and C++ reject integrity, dependency, duplicate-pair/token, vocabulary and length errors. C++ loads this artifact directly; it does not need the old merge text at inference/training time.

The Java-generated [golden cases](tokenizer-golden.tsv) cover the requested words/phrases plus punctuation, numbers, apostrophes, newlines and non-ASCII UTF-8. Java and C++ tests compare exact token IDs and decoded bytes. A focused Java test also refits 1024 BPE from the original Loop 5D balanced train-only sample and compares **all 768 merge rules** with the migrated artifact. Strict Java UTF-8 input and round-trip checks apply to valid Unicode text; individual generated tokens can decode to partial UTF-8 byte sequences until combined.
