# Pretraining data pipeline v1

`PretrainingDataset` ingests a caller-supplied local directory; no network fetch occurs. The convention is `data/raw/` for future local sources, `data/processed/<dataset>/` for token partitions, `data/manifests/` for local manifests, `data/tokenizer/` for the small saved BPE artifact, and `data/checkpoints/<run>/` for run state. Raw, processed, local manifests and checkpoints are Git-ignored. The pilot uses the existing 11-file curated historical/original corpus at `src/test/resources/brain/diverse-english/`; it is **304,963 bytes**, too small for serious 50M pretraining. No larger legitimately usable local corpus was found in the bounded project inspection.

Ingestion discovers `.txt` files recursively to depth 8, sorts relative paths, rejects symlinks/unsupported files, strictly decodes UTF-8, rejects controls outside tab/newline/CR, enforces 16 MiB/file, 16,384 characters/line, 10,000 files and 64 GiB cumulative input limits. An ASCII-letter/whitespace heuristic screens obvious non-English or garbage; it does not certify language. Every discovered file has an accepted/rejected manifest row and explicit reason. SHA-256, byte count and code-point count are recorded. Duplicate document hashes are rejected; accepted files are assigned whole-document sorted 98%/1%/1% splits, capped to preserve at least one validation and test document for small datasets. With 11 documents this is 9/1/1, not numerically 98/1/1.

Exact stripped-line and blank-line-separated paragraph hashes are checked across partitions, with an explicit two-million-distinct-entry audit ceiling. This is a lexical screen, not proof against semantic overlap. No model window crosses a document or partition. BPE is frozen; tokenization resets at each source line as in the Java 5D corpus path. Files are checked against their scan digest again before tokenization. The test partition is prepared and integrity-checked but not evaluated during the pilot.

Each processed partition is a read-only `*.jtok` file. Its 128-byte little-endian header has `JDTOK001`, version 1, partition ID (0 train, 1 validation, 2 test), 32-byte tokenizer SHA-256, 32-byte dataset SHA-256, 64-bit document count, 64-bit token count and 32-byte SHA-256 of the payload. The payload repeats a 64-bit document token count followed by that many 32-bit token IDs. The native reader validates the complete digest/counts/IDs and memory-maps the file; it keeps only document boundaries and bounded window references in RAM. Context stays 32, and stride is configurable. Canonical validation/test order is file order; train references are shuffled once per epoch with seed 42. A current safety cap limits in-memory shuffled references to 10 million; larger runs require an external permutation design. Corrupt payloads and cross-document references are rejected.
